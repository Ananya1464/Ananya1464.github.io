Fragile Features

Are the features safety monitoring depends on the unstable ones?

Sparse autoencoders trained on the same data with different random seeds learn different features, and rare features are the least consistent. Safety concepts like toxicity or refusal are rare in training data. So I wanted to know whether safety monitoring quietly relies on the fragile part.

I tested it first where I know the right answer: synthetic data with 8 rare and 56 common features, three TopK SAEs from different seeds, features matched across seeds with Hungarian matching.

What this does not show

That safety features are unstable in real models. The 0.7 cutoff is arbitrary, the SAEs are tiny, and "rare" only stands in for "safety-relevant." Next: Pythia-160M with three seeds, then checking whether real toxicity and sentiment features land in the fragile group.

Jun 2026real modelsmall sample

Where does GPT-2 keep sentiment?

At which layer does a frozen GPT-2 make sentiment easiest to read?

I froze GPT-2 small and trained a linear probe on each of its 13 layers. The best layer was 6, not the last one. The shape interested me more than the peak: the raw embeddings already reach 76.5%, accuracy dips to 71.8% by layer 3, then climbs back.

What this does not show

Whether the pattern holds in bigger models. One model size, 1,500 training sentences, mean-pooled states. A first look.

Every Pythia model sees the same data in the same order, so comparing sizes isolates size alone. Each step cut perplexity by roughly the same factor, about 0.58×.

What this does not show

Whether the factor holds at 1B and above. I capped the evaluation windows for speed, so absolute values would shift a little.

Prompt injection detection

Can a simple classifier spot prompt injections, and what gives them away?

A 110-prompt benchmark across 7 attack categories. I compared a plain TF-IDF classifier with one trained on Cohere embeddings, using 5-fold cross-validation, and looked at which phrases separate attacks from normal prompts.

Aug 2026synthetic data

Modem test triage agent

Test engineers on RF and modem conformance runs read failure logs one at a time to decide: known issue, or new problem to escalate. An LLM can help with that only if it's willing to say "I don't recognize this."

My agent groups similar failures, checks them against a small knowledge base of known issues, and asks Claude for a root-cause hypothesis per group. Anything it can't place is marked unclassified.

Unknown failures correctly flagged

Text similarity only0/6
+ error-code gate6/6

Known failures still matched after the fix: 34/34. 40 failures became 6 groups to review.

What broke

I invented a failure type with no knowledge-base entry, "baseband clock drift," to test it. The first version matched it to "Power Calibration Drift" because both contained the word drift.

Every log already had a structured error code that I'd ignored. Requiring an exact code match fixed it.

What this does not show

That it survives real logs. All the data is generated by me, and I haven't evaluated the quality of Claude's hypotheses yet.

Jul 2025 – Mar 2026real-world events

Security log analysis platform · ValueMomentum

A pipeline that takes in security logs, checks them for threats four different ways, and groups the results into incidents an analyst can act on. A local LLM summarizes incidents and answers analyst questions. I validated it on 137,611 real endpoint events.

What broke

A senior engineer reviewed my code and found 18 issues, 5 of them critical. There was no authentication. One malformed log message could crash the whole pipeline. A memory leak would have killed the correlation service within about two days.

Fixing those taught me more than building the features did. Threat-indicator lookups also went from a slow scan to 1.66M lookups per second.

Not finished

The dashboard and some data enrichment were still incomplete when I left.

Jul 2025 – Mar 2026mock data only

TPRA AI Assistant · ValueMomentum

Third-party risk assessments are long compliance questionnaires. Experts spend 40–60 hours on each one, mostly answering questions they've answered before. I built an assistant that drafts answers with citations from past answers and company documents.

The part I care about is that it doesn't trust all of its own answers equally. Each answer gets a confidence score. Confident answers are approved automatically, less certain ones go to a person, and anything touching personal data, finance or security gets stricter review however confident the system is. Reviewer decisions feed back into future scores.

What this does not show

Real-world savings. It only ran on 560 mock records, because the credentials for real data sources didn't arrive before my internship ended. The ~75% time saving is a projection, not a measurement.

Jul 2026 – nowin daily use

Life Agent

An agent that keeps track of what I planned, what I finished, and how long I focused. It turns that into a streak, levels and a daily briefing. When I tell it I'm procrastinating, it looks at my real task list, tells me what I already did today, and picks one small next step.

It runs on Claude, Gemini and NVIDIA NIM, syncs with Notion, and moves events from my laptop to the cloud with GitHub Actions. The dashboard regenerates itself, so I can't edit the numbers to look better.
